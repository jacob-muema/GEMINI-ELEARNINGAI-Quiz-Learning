SUBTOPIC 1.1

Describe Cloud Computing

Understand the foundational definition of cloud computing, the shared responsibility model, deployment models, and cloud economics.

1

Definition of Cloud Computing

Cloud computing is the delivery of computing services over the internet ("the cloud") on an on-demand, pay-as-you-go basis. Instead of purchasing, operating, and maintaining physical servers and hard drives, you rent access to services from a cloud provider such as Microsoft Azure.

REAL-WORLD ANALOGY: MUNICIPAL POWER GRID VS. GENERATOR

Imagine you need electricity for your home or business. You don't build your own power plant or invest millions in diesel generators. You simply plug into the electrical grid, switch on the lights, and receive a monthly bill for the exact kilowatt-hours you consumed. Cloud computing works identically: you plug into Azure's global infrastructure and pay only for the compute and storage units you use.

Compute
Processing power, virtual machines, containers, and serverless execution.
Storage
Durable, scalable storage for files, disks, relational tables, and backups.
Networking
Secure connections between resources, load balancers, and firewalls.
Databases
Managed relational (SQL) and NoSQL engines with automatic failover.
2

Shared Responsibility Model

When using cloud services, security and management duties are divided between Microsoft (the cloud provider) and You (the customer). The exact division shifts depending on the cloud service model you select.

Responsibility Matrix by Layer
Architecture Layer On-Premises IaaS PaaS SaaS
Information & Data Customer Customer Customer Customer
Devices & Endpoints Customer Customer Customer Customer
Accounts & Identity (Entra ID) Customer Customer Customer Customer
Applications Customer Customer Customer Microsoft
Operating System (OS Patching) Customer Customer Microsoft Microsoft
Network Controls Customer Customer Shared Microsoft
Physical Datacenter & Hardware Customer Microsoft Microsoft Microsoft
AZ-900 Core Exam Rule: In every cloud model (IaaS, PaaS, SaaS), the customer is always responsible for data security, credentials, and endpoint devices. Microsoft is always responsible for physical datacenter security, power, and physical hypervisor hardware.
3

Cloud Deployment Models

Public Cloud

Owned and operated by a third-party cloud service provider (such as Microsoft Azure). Resources are delivered over the public internet and shared (multi-tenant) across multiple organizations, with strict logical isolation.

No hardware purchase; high scalability; pay-as-you-go pricing.
Private Cloud

Computing infrastructure used exclusively by one single organization. It can be physically located at your organization's on-site datacenter or hosted by a third party.

Complete control and isolation; high capital investment and maintenance responsibility.
Hybrid Cloud

Combines a public cloud and a private cloud (or on-premises datacenter), allowing data and applications to be securely shared between them via VPN or ExpressRoute.

Enables compliance (sensitive data stays on-prem) while leveraging cloud elasticity.
Multi-Cloud

Using services from multiple distinct public cloud providers (e.g. running specific services in Microsoft Azure while utilizing AWS or Google Cloud for other specialized workloads).

Avoids single-vendor lock-in; leverages the unique strengths of each cloud vendor.
4

Consumption-Based Model: CapEx vs. OpEx

Cloud computing operates primarily on a consumption-based model (Pay-As-You-Go). There are no upfront purchase fees; you only pay for the exact resources (virtual machine run-time, storage GBs, network bandwidth) you consume.

TRADITIONAL ON-PREMISES
Capital Expenditure (CapEx)
  • Substantial upfront financial investment in physical servers, storage arrays, cooling, and real estate.
  • Purchased assets depreciate on your accounting balance sheet over 3 to 5 years.
  • High financial risk: buying excess capacity leads to idle waste; buying too little bottlenecks growth.
CLOUD CONSUMPTION
Operational Expenditure (OpEx)
  • Zero upfront hardware purchase costs; pay only for operational subscription services.
  • Billed as an operating expense in the current tax period for immediate tax deduction benefits.
  • Maximum agility: spin up 100 virtual machines for a weekend project, then deallocate them to stop billing immediately.

SUBTOPIC 1.2

Describe the Benefits of Using Cloud Services

Explore high availability, horizontal vs. vertical scalability, elasticity, reliability, predictability, security, governance, and cloud manageability.

1

High Availability & Scalability

Cloud platforms are engineered from the ground up to prevent downtime and scale dynamically with fluctuating user demand.

High Availability (HA)

Focuses on ensuring maximum system uptime and eliminating Single Points of Failure (SPOF). Microsoft Azure guarantees high availability through automated failover across redundant power supplies, servers, Availability Zones, and regional datacenters backed by financially supported Service Level Agreements (SLAs like 99.9% to 99.99%).

Scalability: Vertical vs. Horizontal
Vertical Scaling (Scale Up / Scale Down): Adding more capacity (CPU cores, RAM, disk performance) to an existing single virtual machine. Like upgrading a vehicle's engine.

Horizontal Scaling (Scale Out / Scale In): Adding additional virtual machine instances side-by-side behind a load balancer to divide incoming traffic. Like hiring extra delivery vans during peak shipping season.
KEY CONCEPT: ELASTICITY

Elasticity is the automated ability of cloud infrastructure to dynamically scale out additional servers when incoming user traffic spikes (e.g. during a Black Friday flash sale) and automatically deallocate those servers when traffic returns to normal. This ensures you never run out of capacity and never pay for idle servers.

2

Reliability & Predictability

Reliability & Resilience

The ability of a system to recover from infrastructure disruptions and continue functioning seamlessly. Azure provides built-in decentralized architectures, automated backups, and cross-region disaster recovery (Azure Site Recovery) so single component failures do not bring down business operations.

Predictability (Cost & Performance)

Cost Predictability: Azure provides tools such as the Pricing Calculator and Cost Management Budgets to forecast and cap cloud expenditure.
Performance Predictability: Dedicated compute tiers and autoscaling ensure uniform latency and steady response times for global users.

3

Security, Governance & Manageability

Enterprise compliance and fine-grained cloud management are built directly into Azure's global fabric.

Security & Governance
  • Physical Security: 24/7 armed surveillance, biometric access, and multi-factor perimeter security at every Microsoft datacenter.
  • Built-in Controls: Encryption at rest (AES-256), encryption in transit (TLS 1.3), and DDoS protection.
  • Azure Policy: Automated guardrails that enforce organizational standards (e.g., blocking deployments outside approved geographic regions).
Manageability: In vs. Of the Cloud
  • Management IN the Cloud: Actions performed by the customer (managing VMs, deploying web apps, configuring firewalls via Azure Portal, CLI, PowerShell, and Bicep/ARM).
  • Management OF the Cloud: Actions performed automatically by Microsoft (physical hardware upgrades, hypervisor kernel security patching, server rack cooling, power redundancy).

SUBTOPIC 1.3

Describe Cloud Service Types

Master Infrastructure as a Service (IaaS), Platform as a Service (PaaS), Software as a Service (SaaS), and architectural decision use cases.

1

The Three Primary Cloud Service Models

IaaS

Infrastructure as a Service

MAXIMUM CONTROL

Renting raw virtualized hardware: Virtual Machines (VMs), storage disks, and virtual networks. You are in complete control of the operating system, installed middleware, software configurations, and security patching.

Azure Examples: Azure Virtual Machines, Azure Virtual Network, Azure Blob Storage Disks.
PaaS

Platform as a Service

DEVELOPER AGILITY

A fully managed deployment environment. Microsoft manages the hardware, operating system, and runtime stack. Developers focus 100% on writing application code, APIs, and business logic without server maintenance.

Azure Examples: Azure App Service, Azure SQL Database, Azure Functions (Serverless).
SaaS

Software as a Service

END-USER APPLICATION

A complete, end-user software application hosted, managed, and maintained entirely by the cloud provider. Users simply connect over the web browser or mobile app. Zero infrastructure or code maintenance.

Examples: Microsoft 365 (Word, Excel, Outlook), Microsoft Teams, Dynamics 365, OneDrive.
2

Service Model Decision Framework

Technical Requirement / Scenario Recommended Model Primary Architectural Rationale
Migrating legacy on-premises applications requiring direct OS registry edits ("Lift and Shift") IaaS Gives complete administrative access to the underlying OS configuration.
Building a modern web application or mobile REST API with automatic scaling and zero OS patching overhead PaaS Frees engineers to write code while Azure manages runtime, OS, and server patches.
Deploying corporate email, real-time team messaging, and shared document spreadsheets SaaS Turnkey end-user software requiring zero development or server management.
